### 1. 거래 유형

1. 정산을 통한 적립 (+)
    1. 상태: 대기 / 완료
2. 충전 신청 (+) => 현재 제공 X
    1. 상태: 대기 / 완료
3. 출금 신청 (-)
    1. 상태: 대기 완료

### 2. 입출금 표현

- `+`: 적립
- `-`: 소진

## 3. 출금 신청 (소진)

### 3-1. 입력 정보

- 출금 신청 금액
- 은행명
- 예금주
- 계좌번호

### 3-2. 처리 flow

1. 출금신청
2. 출금신청 이력 저장(완료 상태)
3. 거래내역 저장
4. 충전금 잔액 업데이트

### 3-3. 동시성 이슈 및 중복 요청 방지.

1. 웹으로부터 트랜잭션 ID(요청마다 고유한)를 받는다.
2. Redis에 트랜잭션 ID가 있는지 확인 => 중복요청 이슈 해결
    - key: seller:charge:withdrawal:{transactionId}
    - value: {sellerId}

    1. 있으면 실패 응답(DUPLICATED Request)
    2. 없으면, 트랜잭션 ID를 Redis에 TTL 5분으로 저장.
3. DB에서 seller의 ChargeBalance를 비관락으로 선점에서 조회.
4. ChargeBalance 잔액 확인 (락 보유 상태)
    1. 출금가능: ChargeWithdrawalRequest(success=true) 저장 → 잔액 차감 → ChargeHistory 히스토리 저장.
    2. 출금불가능: ChargeWithdrawalRequest(success=false, 실패 이유=잔액부족) 저장 → 종료.

=> 필요한 작업

1. 충전금출금신청.md 업데이트 transactionId(UUID, 화면 진입시 생성 X, 요청 시 생성) 필드 추가
2. ChargeWithdrawalRequest에 실패 이유 컬럼 추가(엔티티, flyway)
3. 개발
    1. RedisRepositoryImpl 사용할 필요없음. RedisTemplate 직접 사용.

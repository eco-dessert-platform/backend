# Method / Endpoint / 설명

- 커스터머가 장바구니에 담긴 상품의 "선택한 옵션" 드롭다운에서 다른 옵션을 선택했을 때, 해당 CartOption이 가리키는 상품 옵션(Product)을 교체합니다.
- 드롭다운에 노출되는 선택지는 장바구니 조회(`GET /api/v1/customer/carts`) 응답의 `availableOptions`(해당 상품의 전체 옵션 목록)이며, 그중 하나를 클릭하면 이 API가 호출됩니다.
- 수량은 변경하지 않고 유지합니다. 수량 변경은 별도 API(`PATCH /api/v1/customer/carts/options/{cartOptionId}` - quantity)를 사용합니다.
- **현재 미구현 상태입니다.** 기존에는 옵션 자체를 바꾸는 API가 없어 FE에서 기존 옵션 삭제 + 신규 옵션 추가(2회 호출)로 처리해야 했습니다. 이 문서는 신규로 설계된 명세입니다.

| # | Method | Endpoint                                              | 설명           |
|---|--------|--------------------------------------------------------|--------------|
| 1 | PATCH  | `/api/v1/customer/carts/options/{cartOptionId}/option` | 장바구니 옵션 변경 |

> **화면 위치**: 장바구니 > 상품별 "선택한 옵션명" 드롭다운

---

# 도메인 구조 참고

```
Cart (1) ── (N) CartItem (= Board 단위 묶음)
                    └── (N) CartOption (= Product 옵션 + 수량)
```

- CartOption은 `(cart_item_id, option_id)` unique 제약을 가지므로, 변경 대상 optionId가 동일 CartItem 내 다른 CartOption에 이미 존재하면 그대로 교체할 수 없습니다. (아래 에러 응답 참고)

```json
{
  "success": true,
  "code": 0,
  "message": "SUCCESS"
}
```

| key     | 설명       | value 타입 | 옵션    | Nullable | 예시      |
|---------|----------|---------|-------|----------|---------|
| success | 요청 성공 여부 | Boolean |       | N        | true    |
| code    | 응답 코드    | Integer | 0: 성공 | N        | 0       |
| message | 응답 메시지   | String  |       | N        | SUCCESS |

> 옵션 변경 시 가격·재고 등 화면 전반이 갱신되어야 하므로, FE는 이 API 성공 후 `GET /api/v1/customer/carts`를 재호출해 장바구니를 다시 그립니다. 이에 따라 응답에는 변경 결과 값을 담지 않고 `CommonResult`만 반환합니다.

# 에러 응답

| code  | message                                  | HTTP Status | 발생 조건                                              |
|-------|-------------------------------------------|-------------|--------------------------------------------------------|
| -72   | 장바구니 옵션을 찾을 수 없습니다.               | 404         | cartOptionId가 요청 회원 소유가 아니거나 존재하지 않는 경우 |
| -716  | 존재하지 않는 상품입니다.                       | 404         | optionId가 존재하지 않거나, 해당 CartItem의 Board 소속 상품이 아닌 경우 |
| -70   | 장바구니에 추가할 상품 옵션이 중복이 되어선 안됩니다. | 400         | 같은 CartItem 내에 optionId를 가진 CartOption이 이미 존재하는 경우 |
| -68   | 선택하신 수량보다 현재 재고 수량이 부족합니다.       | 400         | 새 옵션의 재고가 기존 수량보다 부족한 경우                  |

# 구현 시 주의사항

### 권한 검증
- 기존 수량 변경 API(`CustomerCartOptionService.findByIdAndMemberId`)와 동일하게, `memberId` + `cartOptionId`로 조회하여 본인 소유 CartOption인지 검증합니다.

### 상품 소속 검증
- 요청 `optionId`(Product)가 해당 CartOption이 속한 CartItem의 Board 소속인지 `Product.validateBelongsTo(board)`로 검증합니다. (다른 상품의 옵션 Id를 잘못 전달하는 경우 방지)

### 중복 옵션 처리
- 변경하려는 optionId가 같은 CartItem 내 이미 다른 CartOption으로 존재하면 단순 교체가 불가능합니다(unique 제약 위반). 이 경우 `DUPLICATED_PRODUCT_OPTION`으로 막고, FE에서는 드롭다운에서 이미 담긴 옵션은 선택 불가 처리(비활성화)하거나 안내 메시지를 노출하는 것을 권장합니다.
- 요청 optionId가 현재 optionId와 동일한 경우(변경 없음)는 그대로 200 응답으로 처리합니다(no-op).

### 재고 검증
- 옵션만 바뀌고 수량은 유지되므로, 새 옵션 기준으로 기존 수량만큼 재고가 있는지 `Product.validateStock(quantity)`로 검증합니다.

### 필요한 도메인 변경 (구현 시)
- `CartOption`에 옵션(Product)을 교체하는 메서드가 아직 없습니다. `updateQuantity`와 동일한 패턴으로 `changeOption(Product newOption)` 추가가 필요합니다.
- `CustomerCartFacade`에 `void changeOption(Long memberId, Long cartOptionId, ChangeCartOptionRequest request)` 메서드 및 `CartRequest.ChangeCartOptionRequest(Long optionId)` DTO 추가가 필요합니다. (반환값 없이 `CommonResult`만 응답)

# Method / Endpoint / 설명

- 커스터머가 특정 주문의 전자영수증을 조회합니다.
- 취소·반품 처리된 주문 항목의 금액은 합계금액에서 제외합니다.
- 결제 수단이 현금(무통장입금, 가상계좌 등)인 경우 카드 관련 필드는 null을 반환합니다.

| # | Method | Endpoint                                  | 설명         |
|---|--------|-------------------------------------------|------------|
| 1 | GET    | `/api/v1/customer/orders/{orderId}/receipt` | 주문 영수증 조회  |

> **화면 위치**: 주문목록 > 주문상세보기 > 영수증보기

### transactionType Enum (거래종류)

| 값                | 설명          | 카드 필드 포함 여부 |
|------------------|-------------|------------|
| `CARD`           | 신용/체크카드     | Y          |
| `BANK_TRANSFER`  | 무통장입금       | N (null)   |
| `VIRTUAL_ACCOUNT`| 가상계좌        | N (null)   |
| `MOBILE`         | 휴대폰결제       | N (null)   |
| `NAVER_PAY`      | 네이버페이       | N (null)   |
| `KAKAO_PAY`      | 카카오페이       | N (null)   |
| `TOSS_PAY`       | 토스페이        | N (null)   |

> `transactionType`은 `Payment.paymentMethod` 값을 그대로 반환합니다.

# 구현 시 주의사항

### 합계금액 계산
- `OrderItem.orderStatus`가 `CANCEL_APPROVED`, `RETURN_COMPLETED` 인 항목은 금액 합산에서 제외합니다.
- `totalAmount = Σ (유효 OrderItem.totalPrice)`

### 카드 정보 필드
- 현재 `Payment` 엔티티에는 `approvalNumber`, `cardType`, `cardNumber`, `installment` 필드가 없습니다.
- PG사(토스페이먼츠 등)의 결제 응답을 저장하는 별도 테이블(`payment_detail`) 추가 또는 `Payment` 엔티티 확장이 필요합니다.

### 권한 검증
- 요청한 커스터머의 `member_id`와 `Order.member.id`가 일치하는 경우에만 응답합니다.
- 불일치 시 `403 Forbidden` 반환.
